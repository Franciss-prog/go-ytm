# 08 — Dynamic theming & transparency (headline feature)

Status: **draft** · Milestones: M4 (Theme struct, static themes, style plumbing), **M4b** (everything else)

## Goals

- UI consumes only semantic tokens; sources (static/pywal/matugen/ansi/file) produce a `Theme`.
- Wallpaper change → running player recolors in < 300 ms, no flicker, no state reset, playback
  uninterrupted.
- Contrast guardrail (WCAG) in OKLCH. Transparent mode that never paints backgrounds.
- Settings popup with live apply and comment-preserving persistence.

## Non-goals

- Real window opacity (impossible from a TUI — the terminal emulator owns it).
- Album-art-derived theme (`source = "album-art"`) — stretch, separate PR after M12.

## Theme model

Token values are Go `image/color.Color` (decided in M0): RGB via `lipgloss.Color("#rrggbb")`,
ANSI palette slots via `ansi.BasicColor`/`ansi.IndexedColor`, and the terminal default via
`lipgloss.NoColor{}` (`theme.Default`). Lip Gloss v2 already understands all three, so no wrapper type.

```go
type Theme struct {
    Name, Source string
    Dark bool                 // drives contrast math + light/dark static variants
    Bg, Fg, Surface, SurfaceAlt, Border, Accent, AccentDim, Muted,
    SelectedBg, SelectedFg, ProgressFilled, ProgressEmpty,
    LyricsPlayed, LyricsCurrent, LyricsUpcoming, Error, Warn, Success color.Color
    Version uint64            // bumped on every apply; part of render cache keys
}
```

`internal/style.Styles` is built from `(Theme, Options{Transparent, Selection, PopupFill, Icons, Profile})`
and is the **only** place `lipgloss.Style`s with colors are constructed. Building it is pure and
cheap (< 1 ms, benchmarked); it is swapped atomically on `ThemeChangedMsg`.

Derivation for missing tokens (any source): `surface = mix(bg, fg, 6 %)`, `surface_alt = mix(bg, fg, 10 %)`,
`border = mix(bg, fg, 25 %)`, `accent_dim = mix(accent, bg, 45 %)`, `muted = mix(fg, bg, 45 %)`,
`selected_bg = mix(bg, accent, 20 %)`, `selected_fg = fg`, `progress_filled = accent`,
`progress_empty = border`, `lyrics_played = muted`, `lyrics_current = accent`, `lyrics_upcoming = fg`,
`error/warn/success` = red/yellow/green hue-shifted to the bg's lightness band. Mixing in OKLab.

## Sources

### `static`
Built-ins embedded as TOML (`internal/theme/builtin/*.toml`, same schema as `theme.toml`).
M4b ships 4: `ytm-dark` (original's #0f0f0f / #ff4e45 look), `ytm-light`, `nord`, `gruvbox-dark`.
M12 goal: 18+ (original's Textual set: textual-dark/light, nord, gruvbox, catppuccin-mocha/latte,
dracula, tokyo-night, monokai, flexoki, solarized-light, rose-pine(+moon/dawn), atom-one-dark/light,
ytm-dark…) — palettes taken from each theme's own published spec, not from memory.

### `pywal`
Reads `pywal_path` or `~/.cache/wal/colors.json`. Fields: `wallpaper`, `alpha`,
`special.{background,foreground,cursor}`, `colors.color0..color15`.

**Real-world finding (owner's machine, 2026-11-16):** the file is written by a *matugen* template
(`pywalfox-colors.json` → `~/.cache/wal/colors.json`) and has **no `special` block** and **empty
strings** for most `colorN` entries (only color0, color10, color13, color15 set). The parser must:
- treat missing `special` as: background ← color0, foreground ← color15 (then color7), cursor ← foreground;
- treat empty/invalid entries as missing (not as errors) and fill via derivation;
- reject only if neither a background nor a foreground can be determined.
This file is a required test fixture (`testdata/theme/pywal/matugen-pywalfox-sparse.json`).

Default mapping (overridable via `[theme.pywal_map]`, e.g. `accent = "color5"`):

| Token | Source |
|---|---|
| bg | special.background → color0 |
| fg | special.foreground → color15 → color7 |
| accent | most chroma-saturated (OKLCH C) of color1..color6 with contrast ≥ 3 vs bg; ties → color4; if all empty → first non-empty of color9..color14 |
| muted | color8 → derived |
| error | color1 → derived red |
| success | color2 → derived green |
| warn | color3 → derived yellow |
| border | color8 mixed toward bg 40 % |
| surface / surface_alt | derived from bg |
| Dark | relative luminance(bg) < 0.5 |

`alpha` (pywal's terminal opacity hint) is informational only — shown in `ytm theme show`, never used
to fake transparency.

### `matugen`
matugen is template-driven, so we ship **`contrib/matugen/ytm-go.toml`** (template) and a config
snippet. Syntax **verified with matugen 4.2.0 locally** (rendered a template from `matugen color hex
"#ff4e45" -m dark|light`): placeholders `{{colors.<role>.default.hex}}` (active mode),
`{{colors.<role>.dark.hex}}`, `{{colors.<role>.light.hex}}`, and `{{mode}}` → `"dark"`/`"light"`.

Template (shipped in M4b):
```toml
# ytm-go palette — generated by matugen, do not edit
mode = "{{mode}}"
[colors]
primary = "{{colors.primary.default.hex}}"
on_primary = "{{colors.on_primary.default.hex}}"
primary_container = "{{colors.primary_container.default.hex}}"
secondary = "{{colors.secondary.default.hex}}"
tertiary = "{{colors.tertiary.default.hex}}"
surface = "{{colors.surface.default.hex}}"
surface_container = "{{colors.surface_container.default.hex}}"
surface_container_high = "{{colors.surface_container_high.default.hex}}"
on_surface = "{{colors.on_surface.default.hex}}"
on_surface_variant = "{{colors.on_surface_variant.default.hex}}"
outline = "{{colors.outline.default.hex}}"
outline_variant = "{{colors.outline_variant.default.hex}}"
error = "{{colors.error.default.hex}}"
```
(Every role name above is re-verified by rendering in the M4b PR; any role matugen doesn't
provide makes the render fail loudly, which is the check.)

Config snippet for `~/.config/matugen/config.toml`:
```toml
[templates.ytm-go]
input_path = '~/.config/ytm-go/matugen-template.toml'   # copy of contrib/matugen/ytm-go.toml
output_path = '~/.config/ytm-go/matugen-colors.toml'
# no post_hook needed: ytm-go watches the output file
```

Mapping (Material You role → token):

| Token | Role |
|---|---|
| bg | surface |
| fg | on_surface |
| surface | surface_container |
| surface_alt | surface_container_high |
| border | outline_variant |
| accent | primary |
| accent_dim | primary_container |
| muted | on_surface_variant |
| selected_bg | primary_container (solid mode) |
| selected_fg | on_surface |
| progress_filled / progress_empty | primary / outline_variant |
| lyrics_current / played / upcoming | primary / on_surface_variant / on_surface |
| error | error |
| success / warn | derived (Material You has no success/warn roles) — hue 140°/85° at primary's L/C |
| Dark | `mode == "dark"` |

### `ansi`
Zero-file mode. Tokens are `ANSI(n)` / `Default`: bg = Default, fg = Default, accent = ANSI 4 (blue)
→ configurable `[theme] ansi_accent = 4`, muted = ANSI 8, error 1, success 2, warn 3, border 8,
selected = reverse video. Rendered as SGR 30–37/90–97 and 39/49, so pywal escape sequences or
kitty/foot/alacritty palette reloads recolor the app instantly with no file watching.
Contrast enforcement is skipped (we can't know the palette) unless the terminal answers OSC 4/10/11
queries (Bubble Tea v2 `BackgroundColorMsg` verified; OSC 4 per-index queries: evaluated in M4b).

### `file`
`[theme] file` or `<config>/theme.toml` with `[colors]` (see 04). Same validation and derivation.

### Fallback
Source missing/invalid → apply `fallback` static theme, one-time toast ("pywal colors not found —
using ytm-dark; will switch when ~/.cache/wal/colors.json appears"), keep watching the directory.

## Color depth

Detect via `colorprofile.Detect(stdout, env)` (TrueColor / ANSI256 / ANSI / Ascii / NoTTY),
override with `[theme] color_depth`. RGB tokens are converted at Styles-build time (not per frame):
256 → nearest in xterm-256 cube+grays by OKLab ΔE; 16 → nearest of the 16 ANSI **assumed** sRGB
values (or real values if OSC 4 answered). Ascii/NoTTY → no colors, reverse/bold/underline only.

## Live reload

```mermaid
sequenceDiagram
  participant FS as fsnotify (parent dir)
  participant W as theme.Watcher goroutine
  participant P as tea.Program
  FS->>W: CREATE/WRITE/RENAME on colors.json
  W->>W: debounce 100 ms (reset on each event)
  W->>W: read + parse + validate + contrast (off UI goroutine)
  alt valid & changed (hash differs)
    W->>P: Send(ThemeChangedMsg{Theme})
    P->>P: Update: styles = Build(theme); themeVersion++ (no other state touched)
    P->>P: View: caches miss on themeVersion → one full repaint
  else invalid / half-written
    W->>W: log warn, keep current theme, retry on next event
  end
```

- Watch the **parent directory** (pywal/matugen replace atomically; a file watch would die on rename).
  If the directory doesn't exist yet, watch the nearest existing ancestor and re-arm when it appears.
- Content hash check avoids repaint when a tool rewrites identical colors.
- Manual triggers: `ytm theme reload` (IPC), `SIGUSR1` (Unix), command palette "Reload theme".
- No flicker: Bubble Tea renders the whole frame atomically; we never emit a clear-screen on reload.
  Scroll offsets, cursor, marks, filters, popup state, and player are untouched (assert in tests).

## Contrast safety

`enforce_contrast = true` (default):
- `fg` vs `bg` ≥ 4.5; `accent`, `lyrics_current`, `error`, `warn`, `success`, `selected_fg` vs their
  background (bg, or selected_bg in solid mode) ≥ 3.0; `muted` ≥ 3.0.
- Algorithm: convert to OKLCH; binary-search L toward the direction that increases contrast
  (lighter on dark bg, darker on light bg), keep hue, reduce chroma only if gamut-clipping; max 24
  iterations. If unattainable (pathological mid-grey bg), fall back to pure black/white for fg.
- `bg` is never modified (it's the wallpaper's identity; in transparent mode we don't know it anyway).
- Transparent mode: contrast is computed against the **assumed terminal background** — pywal
  `special.background`/color0 if source is pywal, `BackgroundColorMsg` (OSC 11) if the terminal
  answers, `COLORFGBG` env, else dark. Adjustments are reported in `ytm theme show` / `doctor`.

## Transparent mode

Honest constraint: **a TUI cannot set opacity**. `transparent = true` means ytm-go never emits a
background color (no SGR `48;…` / `40–47` / `100–107`), so the terminal's own background — opaque,
translucent, or blurred — shows through. Terminal opacity is configured in the terminal emulator.

| Element | Opaque | Transparent |
|---|---|---|
| root / panes / sidebars / bar / table / lyrics | `bg`/`surface` fills | none (SGR 49 / unset) |
| selection | `selected_bg` fill | per `transparent_selection`: `bar` (accent `▌` gutter + bold accent fg, **default**), `reverse` (SGR 7), `underline` (SGR 4 + accent fg), `solid` (keeps `selected_bg` fill) |
| popups | `surface` fill + border | border only; `popup_fill = true` restores `surface` fill |
| progress bar | filled/empty glyph colors | same (fg-only glyphs `━ ╸ ─` / blocks `█ ░`), no bg |
| scrollbar | track bg | glyph-only (`│` track in border color, `┃` thumb in accent) |
| album art (half-blocks `▀` with fg=top px, bg=bottom px) | as is | "background" pixels (ΔE < 6 vs assumed terminal bg, or alpha < 50 %) are left unpainted; see note |

Album art note: each cell encodes two pixels. When exactly one pixel is "background", we draw the
other with fg-only (`▀` or `▄`) and default bg; when both are, a space; when neither, the cell needs
a bg color — **that is the documented tradeoff**: art cells keep bg fills in transparent mode unless
`album_art_mode = "off"`. The transparent-render test therefore exempts the art component's
bounding box (explicitly registered), and only it.

## Settings popup (`,`)

```
 ╭─ Settings ───────────────────────────────────────╮
 │ Theme source        ‹ pywal ›                    │
 │ Theme name          ytm-dark  (static only)      │
 │ Transparent         [x]                     C-t  │
 │ Selection style     ‹ bar ›                      │
 │ Popup fill          [ ]                          │
 │ Album art           ‹ blocks ›                   │
 │ Enforce contrast    [x]                          │
 │ Live reload         [x]                          │
 │                                                  │
 │ ←/→ change · space toggle · enter save · esc     │
 ╰──────────────────────────────────────────────────╯
```
Changes apply live (preview). `enter` persists changed keys via `config.Patch` (comment-preserving,
see 04); `esc` reverts to the values at open. Also reachable from Help and command palette.
`toggle_transparency` (proposed `C-t`) flips and persists `transparent`.

## Edge cases

- pywal file with `alpha` but no colors; all-empty colors; JSON with trailing garbage; 0-byte file
  during write; file deleted (→ keep current theme, toast once, keep watching).
- Very light palettes (light bg) → Dark=false, contrast moves fg darker.
- Low-saturation palettes → accent pick falls back to color4 then raises contrast.
- `NO_COLOR` set → no colors regardless of theme (TUI too), selection via reverse.
- Terminals that don't answer OSC 11 → 100 ms timeout, assume dark.
- tmux: OSC queries may need passthrough; detection degrades to `COLORFGBG`/dark.

## Test plan (required in M4b)

- Golden mapping: `testdata/theme/pywal/*.json` (≥ 5: dark vivid, very light, low-saturation,
  owner's sparse matugen-written file, full 16-color) → `*.golden.toml`; matugen fixtures (dark,

- Contrast property tests (`testing/quick` or rapid-style generators): ∀ random bg/fg/accent, output
  meets ratios (or hits the documented black/white fallback); hue preserved within 2°.
- Reload tests (fake clock for debounce): temp-write + rename; partial write then completion; invalid
  JSON keeps old theme; delete then recreate; directory created later; identical content → no message.
- Transparent render test: registry of every page/component (+ popups); render at 2 sizes; assert
  `style.BackgroundSGRs(out)` is empty (a real SGR parameter parser — a regex mis-reads the `107`
  inside `38;2;255;107;107` as a background code; found in M0) except in registered exemptions (album art box; `solid`
  selection; `popup_fill`). Opaque mode: assert the view sets the terminal background
  (`tea.View.BackgroundColor`; see 05 implementation notes for why the root is not an SGR fill).
- Color depth: table tests truecolor → 256 → 16 → none, known nearest results.
- `config.Patch` tests for every Settings key.
- Benchmark: `BenchmarkThemeApplyAndRepaint` (build Styles + render full screen at 200×60) < 50 ms;
  `BenchmarkStylesBuild`.
